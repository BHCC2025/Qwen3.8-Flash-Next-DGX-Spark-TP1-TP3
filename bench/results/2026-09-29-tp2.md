# TP2 re-bench on kit v0.2.1 — 2026-09-29

**Hardware:** two DGX Sparks (GB10, 128 GB), DGX OS 7, one QSFP cable
**Image:** `vllm/vllm-openai:nightly-8a728663c1c3eeace834a95f5654fa653cc1998c`
**Model:** `nvidia/Qwen3.8-Flash-Next-NVFP4` @ `fc694b54`
**Launcher:** this repo, `./run.sh tp2` with recipe defaults, thinking off
**Suite:** `bench/bench.sh` (the kit's shared suite, unchanged test code), single stream. Raw log: `2026-09-29-tp2.log`

**What changed:** only the NCCL pair profile in `kit/lib/nccl.sh` (dgx-spark-recipe-kit v0.1.2+): the same buffer and
protocol settings as the triangle profile (`NCCL_BUFFSIZE=1M`, `NCCL_LL128_BUFFSIZE=256K`, `NCCL_PROTO=^LL128`,
8 channels). Every other docker argument is identical to the 2026-09-24 run (checked with `DRY_RUN=1`).
`./setup.sh` reports an NCCL all-reduce of ~11.8 GB/s (256 MB) on the cable with these settings.

| Median | 2026-09-24 (kit v0.1.1) | 2026-09-29 (kit v0.2.1) |
|---|---|---|
| Short code, 512 tokens | 51.7 tok/s | 52.9 tok/s |
| Short prose, 512 tokens | 37.6 tok/s | 37.7 tok/s |
| ~9.3K-token prompt, decode | 33.4 tok/s | **39.0 tok/s** |
| Cold prefill, ~7.4K tokens | 2,882 tok/s | 2,855 tok/s |
| Cold prefill, ~25K tokens | 2,858 tok/s | 2,851 tok/s |
| Smoke test (math, fact, code, thinking, tool call) | all pass | all pass |

Notes:
- Decode after a long prompt is 17% faster: those steps all-reduce larger tensors, where the old buffer settings
  were slowest (a 1 MB all-reduce took ~490 µs before, ~140 µs after). Short-prompt decode and prefill are
  unchanged within run-to-run noise.
- TP1 and TP3 do not use the pair profile; their docker commands are identical to 2026-09-24, so their numbers
  stand.
